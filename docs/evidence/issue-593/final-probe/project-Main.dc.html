03机制二 · 在线 softmax（rescaling）
softmax 的分母要看完所有 K 块才知道。所以边走边维护 m（已见最大值）与 ℓ（已见指数和）：
m_new = max(m_old, max(S_ij)) ℓ_new = e^(m_old − m_new) · ℓ_old + ∑ e^(S_ij − m_new) O_ij = e^(m_old − m_new) · O_ij + e^(S_ij − m_new) · V_j
换新最大值时，旧的 O 与 ℓ 乘一个修正因子再相加——结果与一次性 softmax 数学上相同，但不必存下任何一列。

04机制三 · 用重算换显存
反向需要 P。既然没存，就再算一遍：前向只留 O、ℓ、m，反向按块重算 Sᵢⱼ 与 Pᵢⱼ，拿到 dQ 的块后立刻丢掉。 代价是多一次前向的运算量，换来：
· HBM 读写从 O(N²) 量级降到 O(N²·d²/M) 量级（M = 片上 SRAM 大小），长序列时减少数倍 · 不存 N×N 的 S/P → 省显存，可训更长的上下文
05数值影响
在线 softmax 与一次性 softmax 在实数上等价；浮点上每次换最大值都要乘 e^(m_old − m_new) ≤ 1 做缩放，误差随块数累积得更多。 论文报告的实测结论是：反向结果（dQ、dK、dV）与标准实现在容差内一致，不因为重算而变差；FP16 前向时，长序列的极端情况下仍应做梯度检查。 另：FlashAttention 只是更快更省的标准 softmax 注意力——不是稀疏、近似或线性注意力。
06局限：它不解决什么
· 计算量仍是 O(N²·d)：省的是访存与显存，不是 FLOPs；超长序列最终仍受算力限制 · 收益依赖 GPU 的片上内存与专用硬件（分块大小要与 SRAM、寄存器匹配）；在 CPU 或片上空间不足的设备上收益有限 · 需要额外实现与融合：自定义反向、分块调度、对变体（因果掩码、GQA/MQA、滑动窗口）逐一定制 · 实现复杂度高，调参、精度调优成本随之上升；生态（自动微分、算子融合库）配合不到位时优势打折
