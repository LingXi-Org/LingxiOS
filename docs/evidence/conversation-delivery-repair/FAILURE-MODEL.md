# Conversation delivery repair (#42)

Written before implementation. A controlled LingxiLoop reproduction against published 3.8.0 uses the real Worker, HTTP model driver and local PostgreSQL; it observes a reviewed missing visual deliverable committed as partial without a repair when no authoring activation exists. It also proves recovered protocol attempts alone do not imply a failed run. No original production run is attributed by this test.

- Ordinary public turns must repair current deliverable omissions while the existing correction and root budgets permit it.
- A real peer handoff must commit before a peer starts. Only a trusted product policy may explicitly identify that boundary; the conversation flag alone, arbitrary prose and model preference are insufficient.
- A handoff is partial goal progress, never satisfaction or permission. Native resource/skill checks remain authoritative and must not be skipped.
- Explicit human blockers, user input/approval waits and cancellations remain effective. No additional retry may route around them.
- Both parsed self-assessment gaps and semantic-review missing items must use the same scoped exception.
- Repeated omissions exhaust the existing correction budget and preserve honest partial content. The change must not introduce new loops, counters or model calls outside established budgets.
- Product policy is optional and defaults to no deferral; private metadata and provider output must not become trusted policy.

- A terminal partial/blocked work item has a real finished_at and known goal outcome. Public trace must retain that precise state rather than unknown or successful completion; replay must preserve its actual start/end. Waiting work must remain unended.
