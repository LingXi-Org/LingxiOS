## Recovery

Prefer a compatible fix forward. Migration 015 only adds tables/columns. Before continuity activation, packaged `rollback015` safely restores the schema-12 marker after draining Web and Workers. It is idempotent, retains additive structures and rejects rollback once any stable record, migration mapping or segmented evidence exists. The product installation provenance must then be reconciled through its previous officially published package and migration workflow before startup. Do not start schema-12 code against schema 13. After activation use a compatible runtime fix; do not delete stable records, restore deleted copies, reset epochs, or re-capture old source messages. Historical moved documents can be inspected by their original id and version; a path conflict needs a current explicit user correction rather than an automatic reverse move.

Production data migration and rollout are not performed by this contributor. Formal release pin, production drain, migration, backfill and final acceptance are integrator gates.
