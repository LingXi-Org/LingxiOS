# Memory forgetting and model admission

A context reads scope epochs and its request version before inventory and validates them again under work/scope locks before returning. When called by the control plane, that version must also match the control plane's context snapshot. The authoritative first epochs for a work are stored in `agent_work_items.meta.memoryAdmission` as `{fence,requestVersion,epochs:[{tenantId,scopeType,scopeId,epoch,forgottenAt}],calls?:{[callId]:requestVersion}}`. This server-owned record contains no memory bodies. Subsequent contexts and lease retries cannot replace an earlier epoch with a post-forget value. The worker receives `MemorySnapshot.admission=true` and `admissionRequestVersion`; it cannot supply replacement epochs through the model budget API.

Model execution first reserves its normal budget. After model-start/request-start events, the asynchronous publication/onAttempt gate, and any stock `ResourceQuota` capacity wait, it repeats `reserveModelCall` for the **same call ID** with `memoryAdmission:true`. That branch requires an existing, unsettled reservation owned by the live lease. It rechecks the real current read grants and scope epochs from the locked server work row, and performs no budget/ledger insertion or deduction. The short transaction commit is the admission linearization point. No database lock spans a provider call.

The runtime copies the input context version before the logical call's first await. Initial reservation validates it and records that call's version on the already-locked work, only when memory context exists and a normal root-budget call was issued. Context refresh preserves these call bindings. Final admission requires the call binding, current context proof and actual current request revision to agree. A newer context cannot authorize a waiting older call. The existing unsettled call row stays locked until admission commits, serializing concurrent settlement. After all authorization/lock waits, `clock_timestamp()` checks the stored budget deadline and lease expiry; the runtime also checks the returned deadline after the host response. A pre-provider deadline keeps its typed budget/provider timeout and one zero-token settlement; user cancellation remains the user's reason.

The stock quota wrapper advertises `ModelDriver.deferredAdmission` and consumes runtime-owned `beforeProvider` after its final capacity wait; nested queue wrappers pass the gate to the innermost owner. No event, publication hook or async resource wait occurs after that gate and before the stock OpenAI driver's fetch invocation. A custom driver that queues inside its own methods must implement the same public deferred-admission contract and consume `beforeProvider` at its last wait; the runtime cannot inspect arbitrary custom transport internals. Ordinary direct drivers use the method-entry boundary. Runs without a memory context proof do not make the extra database call.

Each retry receives its own normal reservation and final admission. A gate rejection never enters provider retry/fallback and settles the one existing reservation once with zero provider tokens. Cancellation is checked immediately before the driver starts. A request admitted before forget is already started and cannot be unsent; its real measured usage is settled. Forget fences prevent its old source from repopulating memory, and later model attempts in that work reject. This does not promise to cancel all network requests or erase already public conversation messages.

The separate cross-run/session receipt/compaction provenance problem found during independent review remains a different patch owned by the integrator's assigned author. This change alone does not qualify that history boundary. No version bump, new DDL, release or deployment is included.
